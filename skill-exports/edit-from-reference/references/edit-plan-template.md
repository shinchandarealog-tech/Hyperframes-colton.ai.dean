# Edit-plan template

Deliver this BEFORE building anything. The human picks; Claude builds.

## Header

```
<Client> · <topic> — edit plan
Style: <style spec name> (from <reference(s)>) · or "principles + <niche preset>" if no reference
Clip: <file> (<raw/edited>; silences cut <old>s → <new>s if applied) · <W>x<H> <fps> · <N> beats
How I'm adapting the reference: <1–3 lines: footage differences → adaptations>
Heads-up: <burned-in text / framing problems / missing shots / anything that forces a choice>
Caption fixes vs. transcript: <transcription mistakes → correct words>
```

## One block per beat (≈2–5s: one spoken thought or one shot group)

```
Beat <n> · <start>–<end>s · "<exact script line>" (or shot description if no speech)
  A · <name> (suggested) — <pattern ID> · like ref @<timestamp>
      What animates: <what, where, and which word/beat it lands on>
      Why: <the style-spec rule it follows, or the principle>
  B · <name> — <pattern ID> · like ref @<timestamp>
  C · <name> — <pattern ID>   (an upgrade or alternative beyond the reference is fine; label it)
  Notes: ______
```

Rules for the options:
- Option A should follow the **style spec** most faithfully. Label any option that departs from the reference ("upgrade").
- At least one option per beat that **needs no stock** (the client's own footage, a text card, a punch-in).
- Never suggest the same pattern for two consecutive beats unless the reference does exactly that.

## Collecting choices

- **Desktop / browser:** an interactive page (pick per beat, a notes box, a "copy plan" button).
- **Phone / chat app:** multiple-choice questions in chat, ~4 beats per batch, with an "Other" option. Don't send an HTML file the user can't interact with.
- Finish with asset questions ("Do you have more footage of X, or should I source licensed stock?").
